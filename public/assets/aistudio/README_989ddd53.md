## 🎮 Interactive Feature Spotlight: "Destroy my portfolio if you don't like it"

<p align="center">
  <img src="/public/assets/destroyer-banner.png" alt="Destroy Any Website Game Integration Banner" width="100%" />
</p>

> _"In a sea of standard portfolio templates, lasting impact comes from personality, memorable interactivity, and technical craft. Rather than allowing visitors or recruiters to glance and bounce in seconds, this Easter egg invites them to have fun, stay engaged, and remember the creator — while solving a genuine frontend systems challenge under the hood."_

### The Problem: Single-Page Application (SPA) Scraping Constraints

Browser-based destruction games such as SpriteFusion's [_Destroy Any Website_](https://destroy.spritefusion.com/) rely on parsing raw HTML DOM elements via server-side scraper proxies and headless browsers, then projecting those elements into a 2D Matter.js physics engine as destructible solid bodies.

Traditional React SPAs present critical issues for physics scrapers:

1. **Hydration Delays:** External game proxies scrape the initial HTTP response before client-side JavaScript finishes mounting, rendering empty `<div id="root"></div>` containers.
2. **Client-Side Routing 404s:** Directly loading subpaths triggers SPA catch-all rewrites, resulting in custom 404 error screens inside game engines.
3. **Dynamic CSS Transforms & Animations:** Continuous CSS keyframes (`transform`, `transition`, `animation`) cause 2D physics bounding calculations (`getBoundingClientRect()`) to calculate shifting or overlapping collision boxes, breaking destructibility.
4. **Iframe Security Restrictions:** Strict `X-Frame-Options: DENY` headers reject framing requests initiated by web game wrappers.

### The Engineered Solution: Dedicated Static Route (`/destroy`)

To create an authentic, frictionless Easter egg for recruiters and visitors, a specialized static replica target arena was built:

- **Zero JavaScript (`public/destroy/index.html`):** Fully standalone, valid semantic HTML with zero `<script>` tags, zero React hydration overhead, and zero external module dependencies.
- **Frozen Physics-Compliant Engine Rules:**
  ```css
  *,
  *::before,
  *::after {
    animation: none !important;
    transition: none !important;
  }
  ```
  Guarantees that element coordinates remain rigid and frozen in time, providing predictable collision geometry for the physics engine.
- **Discrete Destructible Hitbox Grid:** The Hero headline, status pills, value proposition card, three pill buttons, "Tools I Work With" pills, education card, and individual skill bricks are styled with distinct background fills and borders, creating highly satisfying modular bricks that break apart upon weapon impact.
- **Vercel Edge Rewrite Architecture (`vercel.json`):**
  A customized edge routing pipeline serves the static target directly from the edge cache while allowing iframe integration:
  ```json
  {
    "cleanUrls": true,
    "rewrites": [
      { "source": "/destroy", "destination": "/destroy/index.html" },
      { "source": "/destroy/", "destination": "/destroy/index.html" },
      { "source": "/((?!destroy).*)", "destination": "/index.html" }
    ],
    "headers": [
      {
        "source": "/destroy(.*)",
        "headers": [
          { "key": "Access-Control-Allow-Origin", "value": "*" },
          { "key": "Referrer-Policy", "value": "no-referrer-when-downgrade" }
        ]
      }
    ]
  }
  ```
- **Seamless In-App Access:** Integrated into the portfolio's `Footer.tsx` via an interactive 36×36px action button featuring a custom animated tank icon that expands to reveal _"Destroy my portfolio if you don't like it"_ on hover, automatically launching the game with `?url=chirantanmallick.vercel.app/destroy`.

## 💻 Local Development & Setup Guide

### Prerequisites

- **Node.js**: `v18.x` or higher (Node 20+ recommended)
- **Package Manager**: `npm`, `pnpm`, or `bun`

### Quick Start

1. **Clone the repository:**

   ```bash
   git clone https://github.com/SpicychieF05/portfolio.git
   cd portfolio
   ```

2. **Install project dependencies:**

   ```bash
   npm install
   ```

3. **Start the local development server:**

   ```bash
   npm run dev
   ```

   The application will be accessible at `http://localhost:3000`.

4. **Verify TypeScript compliance:**

   ```bash
   npm run lint
   ```

5. **Generate an optimized production build:**

   ```bash
   npm run build
   ```

   The compiled assets will be output to the `dist/` directory, including the static `/destroy` endpoint.

6. **Preview the production bundle locally:**
   ```bash
   npm run preview
   ```

## 🛡️ Security & Performance Configuration

The application includes production-grade HTTP security headers configured in `vercel.json`:

- **`X-Content-Type-Options: nosniff`**: Prevents MIME-type sniffing vulnerabilities.
- **`X-XSS-Protection: 1; mode=block`**: Enables cross-site scripting filters in legacy user agents.
- **`Referrer-Policy: strict-origin-when-cross-origin`**: Protects privacy across cross-origin requests.
- **CORS for `/destroy`**: Allows open `GET`, `HEAD`, `OPTIONS` methods so external sandboxed games can render the target replica with zero CORS rejections.
- **Immutable Static Caching**: 1-year immutable cache headers (`max-age=31536000, immutable`) for all hashed scripts and assets in `/assets/`.
